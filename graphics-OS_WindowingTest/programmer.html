CODERGIRL / SBOS Programmer API

This page documents the API intended for normal programs (outside GUI internals). Handles in, handles out. No peeking into structs. Future-you will thank you.

Getting Started

Typical flow

SBXWindowId w = SBOS_createWindow(...);

SBControlHandle b = SBOS_addButton(w, ...);

// main loop:
SBOS_MouseInterface(evt, mx, my);
SBOS_paintAllWindows();
Rule: store SBControlHandle and SBXWindowId. Don’t store internal pointers in app code.

Callbacks

Scrollbar callback

typedef void (*SBOS_Callback)(void *sender);

void SBOS_setScrollBarCallBack(SBControlHandle scrollbar, SBOS_Callback cb);
Public docs rule: don’t tell users to cast sender to internal structs. If you want the callback to expose “value”, provide a public getter: SBOS_scrollbar_get_value(handle).

static ItemLists_t items;
static SBControlHandle hList;

void OnScroll(void *sender){
    // In public docs, prefer public getters/setters
    // e.g. int v = SBOS_scrollbar_get_value((SBControlHandle)senderHandle);
    // SBOS_setListbox_top_by_handle(hList, v);
}

void Setup(){
    listitem_init(&items);
    listitem_add(&items, "Alpha");
    listitem_add(&items, "Beta");

    SBXWindowId w = SBOS_createWindow(10, 20, 260, 280,
                                     "List", WIN_DEFAULT_FLAGS);

    hList = SBOS_addListBox(w, 6, 40, 200, 196, &items, 0);
    SBControlHandle sb = SBOS_addScrollbar(w, 206, 40, 16, 196,
                                          SB_ORIENT_VERT, 0, 10, 1, 0, 0);

    SBOS_setScrollBarCallBack(sb, &OnScroll);
}
You can make this example “perfect public API” by exposing: SBOS_scrollbar_get_value(handle) and SBOS_listbox_set_top(handle, top). That removes all internal casting from user code.

Example: Desktop + Windows

This is the “boot into a UI” pattern: init systems, create a desktop window (workbench), then spawn normal windows on top. A desktop is just a window with always-to-back + no border.

Desktop window (Workbench)

void createBasicDesktopTest(){
    initWb();
    initFastRam();  // IMPORTANT: ItemLists use fastAlloc

    // DESKTOP WINDOW (yes it IS a window)
    SBXWindowId workbench = SBOS_createWindow(
        0, 0, SCR_WIDTH, SCR_HEIGHT,
        "Workbench",
        SBX_WF_ALWAYS_TO_BACK | SBX_WF_VISIBLE | SBX_WF_NOBORDER
    );

    SBOS_addBitmapView(workbench, 0, 0, 480, 320,
        backdrop, 480, 320, 480,
        BVF_SRC_ROWMAJOR, GAD_TOOL_NOBORDER
    );

    SBOS_addButton(workbench, 6, 6, 170, 26,
        "a workbench button",
        GAD_TOOL_DEFAULT
    );
}
Note: Your desktop stays behind everything because of SBX_WF_ALWAYS_TO_BACK. That flag is basically “you are the background now” 😂

Example: Scrollbar Callback

Scrollbars can call a custom function when they change. The callback receives a pointer to the scrollbar gadget, so you cast it to GAD_SCROLLBAR_T*.

Callback function

// a CUSTOM function for a scroll bar
void BitDemoScrolly1(void *s){
    GAD_SCROLLBAR_T *sb = (GAD_SCROLLBAR_T*)s;  // cast FIRST
    if (!sb) return;

    printf("Custom Function!: %d\n", sb->value);
}

Attach callback

SBControlHandle scrrb =
    SBOS_addScrollbar(winMain2, 260, 6, 20, 150,
                      SB_ORIENT_VERT, 0, 120, 50, 0,
                      GAD_TOOL_SCROLLARROWS | GAD_TOOL_DEFAULT);

SBOS_setScrollBarCallBack(scrrb, &BitDemoScrolly1);

Rule: callback gets void* so you can keep the public API simple. Internals stay spicy.

Example: Scrollbar Driving a ListBox

This one is genuinely “real UI”: the scrollbar controls the ListBox top index. You store the listbox handle globally (or in your window state), and the scrollbar callback updates the listbox via SBOS_setListbox_top().

Globals

static ItemLists_t demolist;
static SBControlHandle theListBox;

Callback that updates the ListBox

// CUSTOM function for a scrollbar that will interact with a listbox
void ListBoxTopSet(void *s){
    GAD_SCROLLBAR_T *src_sb = (GAD_SCROLLBAR_T*)s;
    if (!src_sb) return;

    GADGET_BASE_T *g = SBOS_gadgetFromHandle(theListBox);
    if (!g) return;
    if (!g->gadget) return;

    SBOS_setListbox_top(g, src_sb->value);
}

Create list, listbox, scrollbar, bind callback

char txt[64];

listitem_init(&demolist);
for(int i = 0; i < 32; i++){
    sprintf(txt, "Listbox test %d", i);
    listitem_add(&demolist, txt);
}

// Create ListBox
theListBox = SBOS_addListBox(winMain, 6, 40, 200, 196, &demolist, GAD_TOOL_DEFAULT);

// Create Scrollbar sized to visible rows:
// total rows = 32, visible rows = 11, so max top = 32 - 11 = 21
SBControlHandle ListBoxScroll =
    SBOS_addScrollbar(winMain, 206, 40, 16, 196,
                      SB_ORIENT_VERT,
                      0, 31 - 11,   // max-top
                      5, 0,
                      GAD_TOOL_SCROLLARROWS | GAD_TOOL_DEFAULT);

SBOS_setScrollBarCallBack(ListBoxScroll, &ListBoxTopSet);
Subtle gotcha: your scrollbar max should match the listbox’s max top: maxTop = itemCount - visibleRows. If those disagree, you’ll get the classic “scrollbar lies, listbox stutters” bug.

Design Laws

• If it’s not SBOS_*, it’s not public API.

• Apps store handles. Internals store pointers.

• Public callbacks should use public getters/setters (avoid “cast the sender” docs).

• Keep ItemLists alive while any control references it.
